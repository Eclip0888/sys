# CompreCheck AI: AI chatbot with real-time evaluation of user comprehension

Thesis system for *Augmentation of Item Response Theory with Answer-Complexity-Based Difficulty and Response-Time
Weighting in an AI Chatbot for Real-Time Evaluation of User Comprehension of AI Outputs* (BS Computer Science,
Pamantasan ng Lungsod ng Muntinlupa).

## What the user sees

1. The user types any question. **Google Gemini** answers it.
2. Directly below the answer, **one multiple-choice question about that answer** appears (generated by Gemini and
   checked for self-consistency). The user taps one option.
3. The **evaluation appears immediately** on the same screen: *Understood*, *Partly understood* or *Not understood*,
   a comprehension score and a plain-language reason.

## The algorithm (`app/engine.py`)

| Step | What happens |
|---|---|
| Complexity | Flesch–Kincaid Grade Level, log word count, technical-term ratio (words of 2+ syllables not on the Dale–Chall list) and the question's cognitive level (`app/complexity.py`) |
| Difficulty (LLTM) | `b = β0 + β · z(features)` so a brand-new answer has a difficulty immediately |
| Tap model | `P(correct) = c + (1 − c − s) · P(understood)`, `P(understood) = 1 / (1 + exp(−a(θ − b)))`, c = 0.25, s = 0.05 |
| Response time | a tap faster than `max(2 s, 0.10 × (3 + words/4))` is a likely rapid guess and gets weight ω_min = 0.2 |
| Ability | weighted EAP over 41 quadrature nodes, updated after every tap |
| Decision | score C = probability that the user understood *this* answer (Bayes' rule over the tap and earlier taps); Understood ≥ 0.70 > Partly ≥ 0.40 > Not. A likely rapid guess is at most "Partly understood". |

## Project layout

```
app/
  engine.py      the evaluation algorithm
  complexity.py  answer complexity features
  gemini.py      Gemini calls (answer, question, self-consistency check) + offline FakeGemini
  qgen.py        question validation and the self-consistency check (up to 3 attempts)
  views.py       account, chat, one-tap response, evaluation card
  admin.py       evaluation log, prompt-set run, simulation, parameters
  jobs.py        background jobs (prompt set, simulation)
  reports.py     Tables 2 and 3, CSV exports
sim/simulation.py   simulation study (ADEMP): data generation, MML calibration, 6 methods, H1–H4 tests
scripts/
  run_prompt_set.py   send the 200 prompts through Gemini from your computer
  run_simulation.py   run the simulation (100 replications × 2 conditions)
  performance.py      timing, memory, CPU and scalability for Table 8
data/prompts_200.csv            the 200 prompts (export of the shared prompt sheet)
data/dale_chall_easy_words.txt  Dale–Chall familiar words (from the textstat package, MIT licence)
tests/                          pytest tests
```

## Run it on your computer

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows      (Mac/Linux: source .venv/bin/activate)
pip install -r requirements-dev.txt
set GEMINI_API_KEY=your-key       # Windows      (Mac/Linux: export GEMINI_API_KEY=your-key)
python wsgi.py                    # open http://127.0.0.1:5000
```

Without `GEMINI_API_KEY` the site runs in **offline demo mode** with placeholder answers, so you can try it first.
The admin pages are at `/admin` (default password `admin`; set `ADMIN_PASSWORD`).

Run the tests with `pytest -q`.

## Put it online (Render + Neon)

1. On https://neon.tech create a free PostgreSQL database and copy its connection string.
2. On https://render.com choose **New → Blueprint** and select this repository (`render.yaml`).
3. Set the environment variables: `GEMINI_API_KEY` (from https://aistudio.google.com), `ADMIN_PASSWORD`,
   `DATABASE_URL` (the Neon string). `GEMINI_MODEL` defaults to `gemini-3.8-flash`; if Google retires it, set it to a current model from https://ai.google.dev/gemini-api/docs/models.
4. Open the Render link on a phone. The free plan sleeps after 15 minutes without visitors; the first visit
   afterwards takes about a minute.

If the main model is busy (503) or out of quota (429), the app automatically tries the models in
`GEMINI_FALLBACK_MODELS` (default `gemini-3.7-flash,gemini-3.5-flash-lite`). The model that wrote each answer is
saved with it (`model` column in the exports).

**Backup provider (optional but recommended):** add `GROQ_API_KEY` (free key from https://console.groq.com).
When every Gemini model fails, the app asks Groq instead (`GROQ_MODELS`, default
`openai/gpt-oss-120b,openai/gpt-oss-20b`; retired models are skipped automatically).

**Never put the API key in the code or in GitHub.** Only in Render's environment settings or your own terminal.

## Thesis workflow

| Step | Where | Output for Chapter 4 |
|---|---|---|
| 1. Prompt set | `/admin/prompts` → Start (or `python scripts/run_prompt_set.py`) | Table 2 (complexity), Table 3 (question generation), `prompt_set_results.csv` |
| 2. Question review | download *review sheet (50 random questions)*, fill the Y/N checklist | researcher-review row of Table 3 |
| 3. Simulation | `/admin/simulation` (100 / 200 / 20) or `python scripts/run_simulation.py` | Tables 4–7 and 9 (`results/simulation_report.md`) |
| 4. Live parameters | `/admin` → *Use parameters from the last simulation* | the chatbot uses the calibrated values |
| 5. Table 8 | `pytest -q`, `python scripts/performance.py` | correctness, time, memory, scalability, CPU |
| 6. Screenshots | chat screen with an evaluation card; admin page | Figures 6 and 7 |

**Gemini quota:** each prompt needs at least 3 Gemini calls (answer, question, check). The free tier has daily
limits, so the prompt-set run may stop with a quota message; press **Start** again the next day and it continues
where it stopped. `GEMINI_RPM` (default 8) limits requests per minute.
